Native EA SPORTS UFC 3 port (PS4 `CUSA06534`, update 1.14) for Windows and Linux.
**No game files are included**: you need your own dump of the game and its 1.14 update.

Local multiplayer with two controllers, louder voices on stereo outputs, fewer GPU hangs and safer
saves on Windows. Most of this release is ported from **PORTHEON** by **@XAndromedaXR**, a GPL fork
of this port that also runs UFC 1, 2 and 4. How to play online:
[HOW-TO-PLAY-ONLINE.md](https://github.com/GNSB/UFC-3-PS4-PORT-LINUX-WINDOWS/blob/main/docs/ufc3/HOW-TO-PLAY-ONLINE.md).

**Extract this release into a new, empty folder.** Do not extract it over or inside an older
version. **The first start rebuilds every shader once**, so the first loading screens are slower.

### New

- **One player per controller (offline).** Every controller after Player 1's is now its own PS4
  user (players 2 to 4), so a second controller can pick a fighter as Player 2, even with two
  identical pads or Parsec's virtual controllers.
  - On by default. The in-game menu (**Insert** or **L3+R3**) has the switch "One player per
    controller" and shows which pad is which player. `local_multiplayer=0` in `bbport.ini`, or
    `BB_LOCAL_MULTIPLAYER=0`, turns it off.
  - If Player 2's controller disconnects, Player 2 stays signed in for 30 seconds and gets the
    same controller back when it reconnects.
  - Online play still uses a single local player.
- **Louder voices and commentary on headphones and stereo speakers.** The game mixes in 7.1. The
  port now folds it to stereo itself, without the extra scaling that left voices at about a third
  of their level. `BB_AUDIO_DOWNMIX=sdl` restores the old mix.
- **Master volume:** `BB_VOLUME` (10 to 400, in percent; default 100), with a limiter so that loud
  moments do not distort.

### Fixes

- **Fewer GPU hangs ("device lost", code 23).**
  - Every loop in a translated shader now stops after 65,536 iterations in a row. A garbage loop
    count in the game's data can no longer run until the driver resets the GPU.
    `BB_SHADER_LOOP_GUARD=0` turns this off, for testing.
  - Image copies and tiling passes are checked against the size of their buffers and images. A
    copy that would go past the end is dropped, and the log says so (`Copy check: …`).
  - GPU crash reports now name the texture involved.
- **Fewer GPU readbacks.** When the game copies memory (with `memcpy`/`memset`) next to data the
  GPU wrote, the port now knows exactly which bytes the copy wrote. It no longer reads those
  pages back from the GPU or marks the write site as a slow one. `BB_HOST_COPY_EXTENTS=0` turns
  this off.
- **Windows: "damaged save" after a Career save.** If another program (often an antivirus) had a
  save file open, replacing it could fail and leave the two halves of a save from different
  moments. The port now retries, using a rename that works on open files. If it still cannot
  replace the file, the previous save stays intact and the log says so.
- **A damaged game file is now named instead of crashing (#31).** If
  `samplegame/data/common/config/memory.cfg` (or `videoheap.cfg`) in your game folder is empty or
  damaged, the game check now says which file it is, and asks you to extract the game and the
  1.14 update again. Before this, the game closed right at start with no clear reason.

### Known issues

- With `BB_WRITE_WINDOW=2`, blood and sweat still do not show (#35). The default (mode 1) is not
  affected.
- CPUs without BMI1/MOVBE/LZCNT (Intel Core 2nd/3rd gen) are still not supported. PR #48 adds a
  translation for them and is under review.
- The 2K/4K internal resolutions are still experimental.
